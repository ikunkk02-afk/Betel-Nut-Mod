# Betel Nut Mod

Betel Nut Mod 是一个面向 Fabric 的 Minecraft 生存扩展模组，围绕槟榔树、槟榔采集、营火烘烤、口味加工、村民交易、Farmer's Delight Refabricated 厨具联动、成瘾与戒断机制，以及槟榔空岛玩法展开。

本模组中的槟榔相关内容仅作为游戏机制与玩法创作使用，不代表现实健康建议，也不鼓励现实中食用槟榔。

## 支持版本

- Minecraft: `1.21.1`
- 当前模组版本: `5.4.0`
- Mod Loader: Fabric Loader `>=0.16.0`
- Java: `21` 或更高版本
- Mod ID: `betel-nut-mod`

## 必需前置

运行本模组需要安装以下前置：

- Fabric Loader `>=0.16.0`
- Fabric API `>=0.116.11+1.21.1`
- Cardinal Components API `6.x`
  - `cardinal-components-base`
  - `cardinal-components-entity`
  - `cardinal-components-world`
- MidnightLib `1.9.2+1.21.1-fabric`

Cardinal Components API 用于保存玩家的槟榔成瘾值、戒断值、上次食用时间，以及空岛生成状态和坐标等数据。

## 可选联动

- Farmer's Delight Refabricated

Farmer's Delight Refabricated 不是强制依赖。未安装时，本模组会保留原版工作台加工路线；安装后，相关口味槟榔的原版工作台配方会通过 Fabric Resource Conditions 隐藏，并改由 Farmer's Delight 的厨具配方提供。

## 主要玩法

- 在世界中寻找或种植槟榔树，获取生槟榔与槟榔叶。
- 槟榔树具有四种树冠组合，叶片姿态、疏密和树高有所变化。果串位于绿色冠鞘下方；持剪刀右键采收会得到完整青果串或黄果串，原位置变为空气，不留果梗。完整树木随后会重新长出青果串，并逐渐成熟。
- 普通破坏或自然凋落的树叶只掉落槟榔叶；青果串拆为 3 个生槟榔，黄果串拆为 5 个生槟榔，或配 1 片槟榔叶制作 1 棵树苗。
- 自然生成以疏林丛林的小片槟榔林为主，普通丛林和竹林中的空地少量分布，丛林附近的河岸高地也可能出现。
- 使用营火将生槟榔烘烤为熟槟榔。
- 将熟槟榔、槟榔叶与对应材料组合，分级加工为多种口味槟榔。
- 食用不同槟榔获得短时增益，同一世界日期只累计一次依赖和口腔暴露天数。
- 食用槟榔后获得槟榔渣，并通过槟榔渣、槟榔渣块和堆肥建立资源循环。
- 长时间停止食用后，玩家会逐步进入戒断状态，并受到负面效果、生命上限惩罚和进食限制等影响。
- 通过左下角紧凑 HUD 查看依赖进度与异常状态，按 H 悬停查看完整身体状态。
- 创建普通槟榔空岛或槟榔一方块空岛世界，在虚空环境中围绕槟榔资源发展。
- 在空岛模式中通过水中召雷仪式或管理员指令补足进入末地的路线。
- 与农民村民交易，获取槟榔相关物品。
- 可通过配置文件调整世界生成、空岛、成瘾、戒断、交易、末影槟榔传送等行为。

## 贝壳、生槟榔与远古物品

普通贝壳可从渔夫村民购买（1 绿宝石换 4 个），或在钓鱼杂物战利品中额外获得。1 个贝壳可磨成 4 份贝壳粉；生槟榔 + 槟榔叶 + 贝壳粉可无序合成 1 个可食用的裹叶生槟榔。

未开启的古城宝箱有 15% 概率额外提供 1～2 个远古贝壳，保留原版战利品。远古贝壳 + 回响碎片 + 2 个裹叶生槟榔可加工为 2 个回响槟榔，提供回响感知：暂时抵抗黑暗，并让附近敌对生物发光；效果结束后有短暂反胃。其基础持续时间为 60 秒，仍受原有增益衰减机制影响。

## 品牌混合装与奖券

新增口味王、和成天下、湘潭铺子三款同人混合装。每包右键打开，获得固定的 6 种不同槟榔各 1 个和 1 张奖券。注意包装的“和成天下”与原有特殊物品“合成天下槟榔”是两个不同物品。

| 包装 | 内含口味 | 农民等级 / 基础价格 |
| --- | --- | --- |
| 口味王 | 熟、辛辣、甜味、清凉、夜行、提神 | 3 / 12 绿宝石 |
| 和成天下 | 熟、蜂蜜、石英、紫水晶、青金石、幻翼 | 5 / 20 绿宝石 |
| 湘潭铺子 | 熟、蜂蜜、甜味、清凉、夜行、辛辣 | 4 / 14 绿宝石 |

2 张纸 + 1 根线可合成 2 个空包装。对应的 6 种槟榔 + 空包装 + 品牌封签可无序合成相应混合装。品牌封签从 2 级农民购买，基础价格 2 绿宝石。打开包装时消耗整包，封签不返还；背包满时物品会掉落在玩家身边。村民交易从候选交易池抽取，因此并非每位农民都出售所有新增物品。

奖券右键刮开，结果由服务器在发券时确定并随物品保存。概率为：未中奖 60%、3 片槟榔叶 25%、1 颗绿宝石 10%、1 个蜂蜜槟榔 4%、收藏用纪念金贝壳 1%。奖券消耗一次，无付费入口。

本轮 12 张物品贴图与 3 张状态图标使用 imagegen 生成并接入游戏。原始透明 PNG、完整提示词和缩放记录见 [美术与验证目录](art-rework/features-v5/README.md)。包装为游戏同人设计，与对应品牌没有合作关系。

## 槟榔树自然生成

从 `4.0.3` 起，槟榔树先寻找合适的林地，再形成错落的小树群。疏林丛林每群目标 4～8 棵，普通丛林和竹林 1～3 棵，丛林附近的河岸高地 2～4 棵；实际数量受地形、空间和群系边界影响。群内树干之间至少间隔 5 格，并混合现有四种树形、树高和果实阶段。

生成地点须有可种植的泥土地、干燥的根部和开阔空间，优先平地或缓坡。河岸高地额外要求附近 24 格范围内有已启用的丛林类群系，8 格内有河流水面，根部地面高于该水面 1～4 格；普通地区的河流不会因此出现槟榔树。竹林自然生成保留，只在有空间的位置尝试。

`config/betel_nut.json` 中原有的 `betelPalmGenerateInJungle` 作为丛林类及邻近河岸生成的总开关；新增 `betelPalmGenerateInSparseJungle`、`betelPalmGenerateInBambooJungle`、`betelPalmGenerateNearJungleRivers` 可分别控制对应地点。保留旧配置的自定义树高、密度和可选海滩/红树林开关，后两项仍默认关闭。

`betelPalmSpawnChance` 控制每次树群生成机会的基础概率，默认 0.08；普通丛林、竹林、河岸分别乘以 0.6、0.4、0.8。原有字段 `betelPalmTreesPerChunk` 现用于每区块树群尝试次数，默认 1，设为 0 可关闭尝试。玩家人工种树不受自然生成群系与河岸条件限制。

此改动只影响新生成的区块。已有树和建筑会保留；在旧世界里需要探索未生成的区域查看新分布。

## 槟榔木材与红石

槟榔木材系列包含木板、楼梯、台阶、栅栏、栅栏门、按钮、压力板、木门和活板门。获得槟榔原木会解锁木板配方；获得槟榔木板会解锁木材衍生物配方。它们可在模组分类和原版建筑方块分类找到，红石部件也加入了原版红石分类。

- 2 块槟榔木板横排合成 1 个槟榔木压力板。玩家、生物和掉落物可以触发，输出 15 级信号，实体离开后自动回弹；旁观者不触发。
- 6 块槟榔木板排列为两列三行，合成 3 扇槟榔木门。支持点击上下半扇开关、红石控制及相邻双门铰链，破坏任意一半或失去底部支撑只掉落一扇。
- 木门的四个方孔可透视；木门、活板门和压力板均支持斧头采掘、木制方块标签和燃料行为。

## 槟榔渣与空岛玩法

从 `4.0.0` 开始，槟榔渣不只是食用后的副产物，也是空岛玩法的基础资源。玩家可以将槟榔渣放入堆肥桶获取骨粉，也可以用 9 个槟榔渣合成 1 个槟榔渣块；槟榔渣块可以拆回 9 个槟榔渣，并可作为扩建平台的基础方块。

模组提供两种空岛世界预设：

- 普通槟榔空岛：生成一座小型虚空岛屿，包含有限开局资源、功能方块、开局箱子和指南书，适合普通空岛生存流程。
- 槟榔一方块空岛：开局只生成 1 个槟榔渣块，并在玩家第一次进入时发放极少量初始物品，后续发展完全依赖玩家建立槟榔资源循环。

空岛只会在选择对应世界预设时启用。普通世界不会自动生成空岛、不会启用空岛虚空保护，也不会触发空岛专属的末地路线。

## 空岛指令与持久化

空岛生成状态通过 Cardinal Components API 的世界组件保存。普通空岛和一方块空岛分别记录生成状态与坐标，玩家对方块的破坏、放置和箱子物品变化由 Minecraft 存档正常保存，退出重进后不会重新覆盖为初始状态。

常用管理指令：

- `/betelskyblock generate`：生成普通槟榔空岛；如果已有生成记录，会提示先执行 reset。
- `/betelskyblock generate_one_block`：生成槟榔一方块空岛；如果已有生成记录，会提示先执行 reset_one_block。
- `/betelskyblock reset`、`/betelskyblock reset_one_block`：只重置生成状态，不会立即覆盖方块。
- `/betelskyblock force_generate`、`/betelskyblock force_generate_one_block`：强制覆盖生成，仅建议管理员在确认目标区域可覆盖时使用。
- `/betelskyblock tp`、`/betelskyblock tp_one_block`：传送到已记录的空岛出生点。
- `/betelskyblock generate_end_portal`：在管理员位置附近生成完整末地传送门结构，受配置项控制。

空岛模式还提供虚空保护。玩家在普通槟榔空岛或槟榔一方块空岛中掉入虚空时，会根据当前模式返回对应出生点；该逻辑不会影响普通世界。

## 配置与数据保存

MidnightLib 配置项用于控制普通空岛、一方块空岛、初始物品、虚空保护、槟榔渣堆肥概率和末地路线等行为。部分配置项会在世界创建或首次生成时生效，修改后可能需要重启游戏或重新创建世界才能完全体现。

Cardinal Components API 当前用于保存：

- 玩家成瘾值、戒断值、上次食用时间、死亡后保留状态和一方块初始物品领取状态。
- 世界空岛生成状态、空岛坐标、一方块坐标和出生点状态。

这些数据用于防止重复生成空岛、重复刷新开局箱子和重复发放一方块初始物品。

## 槟榔树系统

模组加入了槟榔树及对应木质方块，包括原木、木板、楼梯、台阶、栅栏、栅栏门、按钮、压力板、活板门、树叶和树苗。

槟榔树可以通过树苗种植，也可以在世界中自然生成。新配置默认在丛林、稀疏丛林和竹林生成；沙滩与红树林沼泽生成可通过配置开启，已有配置的开关会保留。野生树还会检查温暖、有降水的环境以及不积水的泥土类土壤。生成开关、生成概率、每区块树木数量以及最小/最大树高都可以在配置文件中调整。

5.3.0 的果实来源统一为树上的果串：普通树叶掉落 1 片槟榔叶，不再掉落散果或树苗；剪刀和精准采集仍可收集完整树叶方块用于建筑，农夫乐事砧板将其切为 2 片叶子。

剪刀右键采收青色未成熟果串或黄色成熟果串，每次掉落对应完整果串并消耗 1 点剪刀耐久。工作台可拆分为 3／5 个生槟榔，农夫乐事刀具砧板提供相同产量；只有黄色成熟果串可搭配槟榔叶制作树苗，旧的“生槟榔 + 槟榔叶”树苗配方已替换。

采后由完整树木的结果节点重新长出青果串，每棵树最多 3 串。结果和成熟都需要附近区块加载、充足光照并随原版随机刻推进；不会覆盖已有方块。树干断开、树冠缺失或根部不在适宜土壤上时停止重新结果。已有完整树木也适用，旧版空果梗会在随机刻更新时消失。详见 [果串采收与再生说明](docs/whole-bunch-harvest-5.3.0.md)。

本轮美术重制替换了全部原有物品、木材、副产品、HUD 与模组图标贴图。槟榔树改为细长环纹树干、绿色冠鞘和分段展开的羽状叶，新野生树默认树干高 9–14 格，人工培育为 8–12 格。旧默认树高会升级，自定义树高保留；旧区块不会自动生成新树形。

普通世界树苗自然生长需要充足光照和温暖湿润环境，温和地区可利用附近水源培育；骨粉提供跨气候的人工培育路线。两种槟榔空岛预设保留原有自然生长能力。具体条件、美术总览、生成提示词、原始备份与验证方式见 [本轮重制说明](art-rework/README.md)。

## 营火烘烤

生槟榔可以通过营火烘烤为熟槟榔：

- `raw_betel_nut` -> `roasted_betel_nut`

熟槟榔是大多数后续加工配方的基础材料。

## 工作台加工

从 5.1.0 起，17 种变种槟榔使用分级配方。未安装 Farmer's Delight Refabricated 时，通过工作台无序合成；安装后改用相同材料和产量的烹饪锅配方，工作台路线隐藏。

- 基础口味以 2 个熟槟榔、1 片槟榔叶和调味／魔法材料加工，得到 2 个成品。甜味使用糖，蜂蜜使用蜂蜜瓶，特殊材料与原有增益对应。
- 提神以 2 个甜味槟榔继续加工，岩浆以 2 个火辣槟榔继续加工，均得到 2 个成品。
- 三款复合槟榔各消耗 3 种已有变种、槟榔叶和额外材料，得到 3 个成品；不再消耗工作台、地图或深板岩。
- 回响槟榔使用 2 个裹叶生槟榔、远古贝壳与回响碎片，得到 2 个成品。
- 纸只用于独立包装，不作为槟榔调味材料或锅内输出容器。蜂蜜瓶消耗后返还玻璃瓶。

普通生槟榔的营火烘烤、裹叶生槟榔、贝壳制粉、品牌包装和木材配方保持原样。完整原料、产量和锅内耗时见 [变种槟榔加工配方表](docs/variant-processing-5.1.0.md)。

目前包含的口味与扩展槟榔包括：

- 清凉槟榔
- 夜行槟榔
- 提神槟榔
- 蜂蜜槟榔
- 荧光槟榔
- 幻翼槟榔
- 末影槟榔
- 青金石槟榔

## Farmer's Delight Refabricated 厨具联动

安装 Farmer's Delight Refabricated 后，模组会加载位于 `data/betel-nut-mod/recipe/compat/farmersdelight/` 的联动配方。

当前联动内容包括：

- Cooking Pot 覆盖全部 17 种变种槟榔，与未安装联动时使用一致的原料和产量；清凉槟榔保留海晶碎片与海晶砂粒两条路线。
- Cutting Board 处理槟榔树叶相关材料。
- 联动配方带有 `fabric:all_mods_loaded` 条件，只有检测到 `farmersdelight` 时才会加载。
- 对应的原版工作台变种配方和配方书解锁带有反向条件，检测到 `farmersdelight` 时不会加载。锅内最多使用 6 个原料槽；两颗槟榔须分开放进两个槽位。成品直接进入输出槽，无需额外放入纸或碗；蜂蜜瓶使用后会返还并从锅侧弹出玻璃瓶。

因此，在 REI/EMI 等配方查看器中，安装 Farmer's Delight Refabricated 时应只显示厨具路线；未安装时则显示原版工作台路线。

## 成瘾与戒断系统

从 5.0.0 起，依赖按主世界昼夜日期计算：同一天吃任何数量、任何种类都只增加 1 天，睡觉进入下一天后可再次计入。切换维度、退出重进和死亡不会重复计算同一天。回拨时间不会重复累计已走过的日期。

默认依赖阶段从第 2、3、4、5、7 个食用日开始，第 7 个食用日完全成瘾。`betel_nut.json` 中的 `maxAddictionValue` 可设为 5–8 天，各阶段随上限调整。5.0.0 的旧默认配置自动更新为 7 天；已记录的真实食用天数保留并以新上限封顶。更早的计分制存档按原依赖阶段迁移一次，旧档不会凭空增加口腔暴露。

从 5.0.2 起，每个依赖阶段直接附加“槟榔依赖”负面状态，食用完成立即生效，每秒持续增加饥饿消耗。默认进度如下：

| 有效食用日数 | 依赖负面等级 | 移速 | 挖掘速度 | 攻击力 |
| --- | --- | --- | --- | --- |
| 1 | 无 | 不变 | 不变 | 不变 |
| 2 | I | -5% | -10% | 不变 |
| 3 | II | -10% | -20% | -0.5 |
| 4 | III | -15% | -30% | -1 |
| 5–6 | IV | -20% | -40% | -1.5 |
| 7 | V | -25% | -50% | -2 |

这些属性惩罚按当前依赖天数维持，无需先触发戒断。继续食用、喝牛奶或槟榔的临时戒断缓解不能清除；临时奖励仍可抵消部分属性惩罚。金苹果、附魔金苹果或停用恢复使依赖阶段下降时，负面状态同步降级或移除。旧存档进入游戏后自动补齐对应状态，创造和旁观模式免除该状态。状态图标、背包效果列表、HUD 的症状提示与 H 键详情均显示服务端实际生效的等级。

一个完整、在线观察到的未食用世界日结束后才结算停用天数。离线跨度、登录当天的半天及一次跨越多日的管理员跳时均不补算停用日。停用第 1、2、3 天逐步增加戒断强度，强度受当前依赖阶段限制；从第 3 个完整停用日开始，每天降低 1 天依赖。各玩家独立结算。

牛奶提供默认 60 秒临时戒断缓解；普通金苹果默认减少 1 天依赖；附魔金苹果默认减少 5 天依赖、清除当前戒断并减少 10 天口腔暴露。反复食用槟榔只提供临时缓解，不会清除长期暴露。旧的每种槟榔成瘾增量和按分钟增长的配置字段保留供旧档兼容，新日历结算不使用这些字段。

## 口腔病变与无法张嘴

口腔暴露独立累计，每个食用日期增加 1 天；停用降低依赖，但不自动抹除已有暴露。默认阈值和效果如下，均为虚构游戏数值，不对应现实病程：

| 效果 | 累计暴露日 | 行为 |
| --- | --- | --- |
| 口腔癌 I | 3 | 最大生命减少 2 点 |
| 口腔癌 II | 5 | 最大生命减少 4 点，仅可吃软食；完整金苹果、附魔金苹果和槟榔禁用 |
| 口腔癌 III | 7 | 最大生命减少 6 点，附加“无法张嘴” |

二级软食包括面包、熟马铃薯、南瓜派、蛋糕、汤与蜂蜜瓶，可通过 `withdrawal_stage2_allowed_foods` 标签扩展。完整金苹果、附魔金苹果和槟榔不受旧版软食配置放行。

三级口腔癌或“无法张嘴”时，所有普通食物均禁用，包括面包、蜂蜜瓶和汤；可饮用金苹果糨糊、附魔金苹果糨糊、缓解药剂、牛奶与药水。高强度戒断也能触发无法张嘴。服务端同时检查开始使用和完成食用，放置的蛋糕和蜡烛蛋糕也检查，无法通过预先开始吃东西或放置蛋糕绕过限制。创造和旁观模式不限制进食。

5.0.3 将旧的默认 12／21／30 天门槛自动升级为 3／5／7 天，保留自定义门槛与开关。暴露达到 7 天立即附加口腔癌 III 和无法张嘴；仅跳过日期而未食用不会增加暴露。5.2.0 起，默认二级病变会提前阻止继续咀嚼槟榔；旧档累积暴露、管理员设置或自定义病变阈值仍按实际状态施加限制。食用、重进、重生和状态被清除后的下一服务器刻均自动补齐真实效果。

牛奶在原版清除临时效果后立即恢复已有病变状态，不会短暂丢失口腔癌或三级病变引起的无法张嘴；只有戒断引起的无法张嘴可获得临时缓解。附魔金苹果糨糊的魔法恢复可降低暴露并降级病变；管理员可用 `/betel oral set <days>` 测试各级状态（3、5、7），用 `/betel addiction clear` 清空全部状态。口腔病变开关和三级阈值可在 `betel_nut.json` 中调整。

## 可饮用恢复用品

三种用品都无需咀嚼，满饥饿值也可饮用，耗时 1.6 秒，饮用后返还一个玻璃瓶，最多堆叠 16 个。两种糨糊保留对应原版金苹果的饱食、增益与模组恢复能力，附魔糨糊具有附魔光效。

| 物品 | 工作台无序合成材料 | 默认恢复 |
| --- | --- | --- |
| 金苹果糨糊 | 金苹果 + 蜂蜜瓶 + 玻璃瓶 | 减少 1 天依赖，降低当前戒断，不修复累计口腔暴露 |
| 附魔金苹果糨糊 | 附魔金苹果 + 蜂蜜瓶 + 玻璃瓶 | 减少 5 天依赖、清除当前戒断、减少 10 天口腔暴露，保护 5 分钟 |
| 缓解药剂 | 蜂蜜瓶 + 蒲公英 + 糖 + 玻璃瓶 | 每天一次：依赖、口腔暴露各减 1 天，清除当前戒断并保护 2 分钟 |

安装 Farmer's Delight Refabricated 后，改为在加热厨锅内处理相同材料，再用玻璃瓶盛出一份；对应工作台配方隐藏。蜂蜜瓶原有的空瓶额外正常返还，装成品的瓶子仍需提供。

缓解药剂以主世界日历为准，每名玩家每天最多生效一次，重复饮用、没有需要恢复的状态时都不消耗；次数保存在玩家数据中，重进、重生和时间回退不会重置。它提供可重复获得的渐进恢复路线，例如 7 天暴露连续用药三个世界日后降为 4 天，允许恢复普通进食。此为虚构游戏机制。

完整说明见 [5.2.0 恢复与进食规则](docs/recovery-and-food-5.2.0.md)。普通槟榔加工及 5.1.0 全部变种配方保持不变。

## 成瘾 HUD 系统

HUD 默认位于左下角，正常状态约 124×26 GUI 像素，仅显示小物品图标、依赖阶段、食用日进度和分段条；图标下的绿点表示今天已计入。口腔癌、进食限制或戒断出现时才增加一行异常提示。没有依赖与病变时隐藏；打开背包、聊天、菜单、F3 或关闭游戏 HUD 时也隐藏。

大 GUI 比例下，默认锚定位置会自动避开快捷栏与生命条。旧版默认左上角位置自动迁到左下角，玩家自己拖动过的位置、缩放和开关保留。按 **H** 打开编辑界面，鼠标悬停状态条可查看完整数据（停用天数、进食范围等）。

玩家也可以根据自己的习惯调整 HUD 位置，或者进入 HUD 编辑模式直接拖动 HUD。HUD 位置设置会保存在客户端本地，不会影响服务器成瘾、戒断和惩罚逻辑。

## HUD 位置调整

玩家可以通过客户端配置或 HUD 编辑模式调整槟榔成瘾 HUD 的位置。

如果已设置按键绑定，可以在游戏控制设置中找到：

- 调整槟榔 HUD 位置

默认按 **H** 进入编辑模式，按住 HUD 并拖动即可调整位置。松开鼠标或按 ESC 后，位置会自动保存。仅悬停查看详情不会改变自动锚定位置。

## 村民交易

三个现有职业共提供 24 条槟榔交易候选，保留原版随机抽取、职业升级、补货和折扣：

- 农民：一级收购生槟榔、青黄果串与槟榔叶；二级出售树苗、烤槟榔、空包装与封签；三级以上逐步提供成对口味槟榔和品牌混合装，五级保留合成天下材料交换。
- 渔夫：一级 1 绿宝石换 4 个贝壳，二级可买贝壳粉。
- 牧师：一级 2 绿宝石加空瓶换缓解药剂；二级带金苹果委托制作糨糊；三级可直接用 8 绿宝石加空瓶购买普通糨糊；五级可带附魔金苹果委托制作附魔糨糊。

`/betel trades info` 显示当前基础报价，`/betel reload` 更新新生成报价与开关。老村民已保存的价格和库存保留。完整交易表与配置说明见 [村民职业交易 5.4.0](docs/villager-trades-5.4.0.md)。

## 安装方法

1. 安装 Minecraft `1.21.1` 的 Fabric Loader。
2. 安装 Fabric API。
3. 安装 Cardinal Components API。
4. 将本模组 jar 文件放入 `.minecraft/mods` 目录。
5. 如需 Farmer's Delight Refabricated 厨具联动，将 Farmer's Delight Refabricated 一并放入 `mods` 目录。

首次启动后，模组会在配置目录生成 `betel_nut.json`，可按需要调整玩法参数。客户端 HUD 设置会保存在 `betel_nut_mod_client.json` 中，用于记录每位玩家自己的 HUD 显示偏好。

## 构建方法

本项目使用 Gradle 与 Fabric Loom 构建。

常用开发命令：

```bash
./gradlew build
./gradlew checkSkyblockPersistence
./gradlew runClient
```

在 Windows PowerShell 中也可以使用：

```powershell
.\gradlew.bat build
.\gradlew.bat checkSkyblockPersistence
.\gradlew.bat runClient
```

`checkSkyblockPersistence` 是脚本化资源检查任务，用于确认空岛 CCA 保存字段、reset/generate 行为和开局箱子不重复刷新的关键约束仍然存在。
